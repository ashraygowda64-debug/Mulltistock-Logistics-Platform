SYSTEM OVERVIEW
================================================================================

The MultiStock platform implements a comprehensive 7-tier Role-Based Access
Control (RBAC) system with granular permissions across 40+ modules.

ROLES IMPLEMENTED: 8
- SuperAdmin (Platform Owner)
- Admin (Business Owner)
- SubAdmin (Manager)
- Supervisor (Senior Staff)
- Staff (Employee)
- Customer (Buyer)
- Customer Seller (Marketplace Seller)
- Guest (Unauthenticated)

MODULES COVERED: 40+
PERMISSION TYPES: 10+ per module
TOTAL COMBINATIONS: 3000+

================================================================================
IMPLEMENTATION STATUS
================================================================================

✅ BACKEND PROTECTION
- Permission decorators: @require_permission('module', 'action')
- Role decorators: @require_role('role1', 'role2')
- API permission classes: CustomPermission(BasePermission)
- Middleware enforcement: RoleBasedAccessMiddleware
- Database filtering: User-scoped queries

✅ FRONTEND HIDING
- Template context: user_role, permissions
- Conditional rendering: {% if permissions.module.action %}
- Sidebar customization: Staff vs Customer sidebars
- Button visibility: Based on permissions
- JavaScript checks: Role-based UI updates

✅ API SECURITY
- DRF permission classes on all ViewSets
- Token authentication required
- CSRF protection enabled
- Rate limiting configured
- Audit logging active

================================================================================
ROLE CAPABILITIES
================================================================================

SUPERADMIN (Highest Authority)
✅ Full CRUD on all modules
✅ User management (all roles)
✅ Permission management
✅ System configuration
✅ Data purge (with verification)
✅ Backup & restore
✅ Audit log access

ADMIN (Business Owner)
✅ Full operational control
✅ Product/Order/Customer management
✅ Create users (limited roles)
✅ Grant permissions (limited)
✅ Financial operations
✅ Analytics and reports
❌ Cannot delete users
❌ Cannot purge data

SUBADMIN (Manager)
✅ Edit products (no create/delete)
✅ Full order management
✅ Customer/Supplier management
✅ Create Supervisor/Staff users
✅ Process orders and returns
❌ Cannot create/delete products
❌ Cannot approve expenses
❌ No permission management

SUPERVISOR (Senior Staff)
✅ View products (no edit)
✅ Create and manage orders
✅ Add/Edit customers
✅ Stock adjustments
✅ Process returns
❌ Cannot edit products
❌ Cannot approve anything
❌ Cannot create users

STAFF (Employee)
✅ View products
✅ Create orders
✅ Process sales
✅ Basic customer service
❌ Cannot edit products
❌ Cannot manage inventory
❌ Cannot access analytics

CUSTOMER (Buyer)
✅ Browse products
✅ Create orders
✅ View own order history
✅ Participate in forums/auctions
✅ Create support tickets
❌ No backend access
❌ Cannot view other customers

CUSTOMER SELLER (Marketplace Seller)
✅ Create own product listings
✅ Manage own inventory
✅ Process own orders
✅ View own sales analytics
✅ Manage marketplace presence
❌ Cannot access other sellers' data
❌ Cannot moderate marketplace

GUEST (Unauthenticated)
✅ View products (if public)
✅ View marketplace
✅ View forums (read-only)
❌ Cannot create orders
❌ Cannot access backend
❌ Cannot post or interact

COMMON SCENARIOS

SCENARIO 1: Product Management
- SuperAdmin/Admin: Can create, edit, delete
- SubAdmin: Can edit only
- Supervisor/Staff: Can view only
- Customer: Can browse only
- Seller: Can manage own products only

SCENARIO 2: Order Processing
- SuperAdmin/Admin/SubAdmin: Full control
- Supervisor: Can create and edit
- Staff: Can create only
- Customer: Can create own orders
- Guest: Must login first

SCENARIO 3: Analytics Access
- SuperAdmin/Admin: Full access
- SubAdmin: Limited access
- Supervisor: Basic reports
- Staff/Customer: No access
- Seller: Own sales only

SCENARIO 4: User Management
- SuperAdmin: Can create any role
- Admin: Can create lower roles
- SubAdmin: Can create Supervisor/Staff
- Others: No access

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: User sees button but gets permission denied
FIX: Add template condition {% if permissions.module.action %}

ISSUE: API returns 403 Forbidden
FIX: Check user role and grant permission

ISSUE: Sidebar shows wrong items
FIX: Ensure base.html loads correct sidebar based on user.is_staff

ISSUE: Permission changes not reflected
FIX: Logout and login again to refresh session
